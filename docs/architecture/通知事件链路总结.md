# 通知事件链路总结

更新时间：2026-06-19

## 一句话结论

Linksee 的通知不应该等同于“所有事件都弹消息”。合理目标是：

- 重要协作变化写入课程/小组会话，形成可追溯记录。
- 状态类变化通过 Socket 刷新页面、角标和待办，不一定进入聊天。
- 高频、低价值、批量导入类事件默认降噪，避免打扰用户。
- 成绩、反馈、截止、被指派任务这类影响行动的事件必须明确提醒。
- 人员授权、助教绑定、教师移除这类管理事件不刷课程群，但要给受影响用户和教务/管理侧明确提醒。

本文件是目标通知策略，不只是当前代码清单。当前实现已经覆盖课程/小组消息、小任务、提交、批阅、成绩等基础实时事件，但仍需要按下面策略补齐“哪些应该提醒、哪些不需要提醒”的产品层规则。

## 通知分层

| 层级 | 载体 | 是否落库 | 是否用户可见 | 适合内容 |
| --- | --- | --- | --- | --- |
| L1 会话消息 | `course.message.*` / `group.message.*` | 是 | 聊天/会话列表显示 | 课程公告、小组动态、任务提醒、提交动态 |
| L2 待办提醒 | 业务事件 + 前端待办/角标 | 业务数据落库 | 看板、红点、列表数量 | 待批阅、待修改、待发布成绩、逾期 |
| L3 页面刷新 | Socket 事件 | 可缓存事件 | 页面数据刷新，不一定弹出 | 成员变化、状态变化、看板聚合更新 |
| L4 审计日志 | 审计/业务表 | 是 | 管理侧或详情页查看 | 成绩发布/调整、强制调组、权限变更 |
| L5 用户级管理通知 | 用户通知表或 `user:{userId}` 通道 | 建议落库 | 通知中心、待办、顶部提示 | 助教绑定/解绑、账号停用、被指派为课程教师 |

建议原则：

1. 需要用户采取行动的事件，至少进入 L2。
2. 需要协作成员共同知晓的事件，进入 L1。
3. 只影响当前页面数据一致性的事件，进入 L3。
4. 涉及责任和追溯的事件，进入 L4。
5. 只影响某个用户权限范围的管理事件，进入 L5，不进入课程/小组群聊。

## 会话模型取舍

MVP 阶段不建议为每个用户建立独立私聊会话，但建议保留“用户级管理通知”的概念。

保留两类主会话即可：

- 课程会话：`course:{courseId}`，承载课程公告、项目/阶段开始、课程层讨论。
- 小组会话：`group:{groupId}`，承载小组讨论、任务动态、提交动态、反馈提醒。

个人级通知中心可以作为后续增强，但不建议在 P0 中引入。原因是 P0 的核心场景围绕课程和小组，用户级 inbox 会增加投递、已读、聚合、去重和补发复杂度。

需要注意：助教绑定、助教解绑、教师被指派等事件不适合放进课程群，也不适合建立私聊会话。更轻的方案是：

- 后端写一条用户级通知或审计记录。
- 在线时推送到 `user:{userId}` 或等价的个人通知通道。
- 离线后登录时从通知列表读取。
- 教务或课程监管角色看到聚合后的管理通知，而不是收到每条课程群消息。

## 应该加入通知的事件

以下是从完整教学链路角度建议加入或强化的通知，不完全等同于当前实现。

### P0 必须通知

| 场景 | 推荐层级 | 推荐载体 | 接收者 | 原因 |
| --- | --- | --- | --- | --- |
| 课程激活 | L1 + L3 | 课程系统消息 + 课程状态刷新 | 课程成员、老师、助教 | 学生需要知道课程正式开始 |
| 课程归档 | L1 + L3 | 课程系统消息 + 课程状态刷新 | 课程成员、老师、助教 | 结束状态需要可追溯 |
| 项目激活 | L1 + L3 | 课程公告 + 项目状态刷新 | 课程成员 | 学生需要知道新项目开始 |
| 阶段开放 | L1 + L2 + L3 | 课程公告 + 学生待办 | 相关学生、小组、老师 | 直接影响提交任务 |
| 阶段即将截止 | L2，必要时 L1 | 待办/红点；临近 24h 可写小组提醒 | 未提交小组、组长、相关成员 | 防止漏交，适合录屏展示 |
| 阶段逾期未提交 | L2 + L3 | 教师待办 + 学生状态提示 | 老师、助教、未提交小组 | 老师需要追踪风险，学生需要知道不可继续提交或需联系老师 |
| 小组确认成组 | L1 + L3 | 小组系统消息 + 小组状态刷新 | 小组成员、老师 | 小组会话启用，需要明确入口 |
| 小组成员加入/移除/换组 | L1 或 L3 | 小组系统消息或成员列表刷新 | 受影响小组、老师 | 对协作关系有影响，至少受影响小组要可见 |
| 组长变更 | L1 + L3 | 小组系统消息 + 成员角色刷新 | 小组成员、老师 | 影响权限和责任 |
| MiniTask 创建且指派成员 | L1 + L2 + L3 | 小组任务消息 + 被指派人待办 | 被指派学生、小组成员 | 明确行动责任 |
| MiniTask 截止提醒/逾期 | L1 + L2 | 小组提醒消息 + 被指派人待办 | 被指派学生、组长 | 防止小组内部任务掉线 |
| 阶段提交成功/重交 | L1 + L2 + L3 | 小组提交动态 + 教师待批阅 | 小组成员、老师、助教 | 学生需要确认提交，老师需要进入批阅 |
| 开始批阅 | L3 | 提交状态刷新 | 小组成员、老师、助教 | 主要是状态变化，不必打扰聊天 |
| 批阅反馈创建 | L1 + L2 + L3 | 小组反馈提醒 + 学生待办 | 小组成员、老师、助教 | 学生需要查看反馈和修改要求 |
| 需要修改 | L1 + L2 + L3 | 小组提醒 + 学生待办 | 小组成员、组长 | 这是明确行动项，必须提醒 |
| 批阅通过/拒绝 | L2 + L3，必要时 L1 | 状态提示；可选小组消息 | 小组成员、老师 | 结果重要，但不一定需要刷屏 |
| 成绩发布 | L1 + L2 + L3 + L4 | 小组成绩提醒 + 学生成绩可见 + 审计 | 小组成员、老师 | 对学生最敏感，必须明确提醒 |
| 已发布成绩调整 | L1 + L2 + L3 + L4 | 小组成绩调整提醒 + 审计 | 小组成员、老师、教务视角 | 涉及责任追溯，必须留痕 |
| 教务指派课程教师 | L5 + L3 + L4 | 用户级通知 + 课程教师列表刷新 + 审计 | 被指派教师、教务 | 教师需要知道自己新增课程权限 |
| 教务移除课程教师 | L5 + L3 + L4 | 用户级通知 + 课程教师列表刷新 + 审计 | 被移除教师、教务 | 权限范围发生变化，必须可追溯 |
| 老师绑定课程助教 | L5 + L3 + L4 | 用户级通知 + 助教课程列表刷新 + 审计 | 被绑定助教、绑定老师、教务/课程监管 | 助教需要知道新增授权课程，教务需要可监管 |
| 老师解绑课程助教 | L5 + L3 + L4 | 用户级通知 + 助教课程列表刷新 + 审计 | 被解绑助教、解绑老师、教务/课程监管 | 助教权限被收回，必须明确提醒 |
| 老师创建助教账号 | L5 + L4 | 用户级通知或首次登录提示 + 审计 | 新助教、创建老师 | 助教需要知道账号已创建和初始登录要求 |
| 助教账号停用/恢复 | L5 + L4 | 用户级通知 + 审计 | 助教、所属老师、教务/课程监管 | 账号状态影响登录和课程权限 |

### P1 可以加入

| 场景 | 推荐层级 | 说明 |
| --- | --- | --- |
| 教师新建课程草稿 | L3 | 仅教师/教务后台刷新，不需要通知学生 |
| 助教绑定或解绑详情变更 | L5 + L3 + L4 | 被绑定/解绑助教和教务侧应收到管理通知，不建议课程群广播 |
| 批量导入学生完成 | L2 或 L3 | 教务/教师看到导入结果，不通知所有学生 |
| 文件上传完成 | L3 | 文件列表刷新即可；除非是提交动作的一部分 |
| 文件处理失败 | L2 | 只通知上传者或老师，不发群消息 |
| 课程成员批量变化 | L3 | 列表刷新即可；可以聚合成一条管理侧摘要 |
| 老师发布课程公告 | L1 | 本质就是课程消息，应进入课程会话 |
| @某人 | L1 + L2 | 被 @ 用户出现未读/高亮，普通成员只看到普通消息 |
| 审计类操作完成 | L4 | 例如成绩调整、强制换组，管理端可查，不一定群发 |

### P2 后续增强

| 场景 | 推荐层级 | 说明 |
| --- | --- | --- |
| 每日/每周课程摘要 | L2 | 汇总待办、逾期、待批阅，适合通知中心或邮件 |
| AI 评语草稿生成完成 | L2 | 只提醒老师/助教 |
| GitHub/CI 同步完成或失败 | L2 + L3 | 只对关联小组和老师可见 |
| 文件转码/预览生成完成 | L3 | 文件状态刷新；失败再提醒上传者 |

## 不建议加入通知的事件

以下事件不建议弹消息，也不建议写入课程/小组聊天；最多做页面刷新、审计或聚合摘要。

| 场景 | 建议处理 | 原因 |
| --- | --- | --- |
| 用户登录/登出 | 不做业务通知，只做安全日志 | 太高频，和课程协作无关 |
| 普通个人资料修改 | 不通知 | 低价值 |
| 教务创建课程草稿 | 只刷新教务列表 | 学生和老师还不需要知道 |
| 草稿项目/草稿阶段编辑 | 只刷新编辑页 | 未发布内容无需打扰学生 |
| 批量导入名单中的每个学生 | 聚合成一条导入结果 | 单条通知会刷屏 |
| 老师查看了提交 | 不通知 | 无行动价值，容易制造压力 |
| 助教打开批阅页面 | 不通知 | 只在状态变为 under_review 时刷新即可 |
| 聊天消息已读 | 不广播 | 只更新当前用户已读状态 |
| 实时心跳、presence check | 不进入业务通知 | 技术状态，不是业务信息 |
| 文件上传进度 | 只在上传者本地显示 | 不需要全员可见 |
| 自动保存草稿 | 只本地提示或编辑页状态 | 高频低价值 |
| 看板聚合数变化 | 只刷新看板 | 除非达到风险阈值，不弹消息 |

## 目标事件矩阵

| 业务动作 | 目标事件 | 是否聊天显示 | 是否待办/角标 | 是否审计 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 课程激活 | `course.conversation.activated` + `course.message.created` | 是 | 可选 | 否 | 当前实现方向合理 |
| 课程归档 | `course.message.created` + 状态刷新 | 是 | 可选 | 否 | 保留系统通知 |
| 项目激活 | `assignment.activated` 或课程公告 | 是 | 是 | 否 | 当前目录有 `assignment.created`，建议语义改为 activated 更贴近通知 |
| 阶段开放 | `stage.opened` 或课程公告 | 是 | 是 | 否 | 当前 `stage.created` 语义偏弱，建议区分 created/opened |
| 阶段截止前提醒 | `stage.deadline.reminder` | 可选 | 是 | 否 | P0 建议至少支持 24h 提醒 |
| 阶段逾期未提交 | `submission.status.updated` | 否 | 是 | 否 | 老师看板和学生提交状态必须刷新 |
| 小组确认成组 | `group.message.created` + `group.member.updated` | 是 | 可选 | 否 | 当前实现方向合理 |
| 组长变更 | `group.message.created` + `group.member.updated` | 是 | 可选 | 否 | 推荐保留消息显示 |
| 成员批量导入 | `course.member.updated` | 否 | 否 | 可选 | 聚合刷新即可 |
| 教师指派/移除 | 建议 `course.teacher.assigned/removed` + 用户级通知 | 否 | 被影响教师有提示 | 是 | 不发课程群，教务可见 |
| 助教绑定 | 建议 `course.assistant.bound` + 用户级通知 | 否 | 助教有提示 | 是 | 助教获得课程权限，应刷新助教课程列表 |
| 助教解绑 | 建议 `course.assistant.unbound` + 用户级通知 | 否 | 助教有提示 | 是 | 助教失去课程权限，应从课程工作台移除 |
| 助教账号创建/停用 | 建议 `assistant.account.created/updated` + 用户级通知 | 否 | 助教/所属老师有提示 | 是 | 不进入课程群 |
| MiniTask 创建并指派 | `group.message.created` + `group.minitask.updated` | 是 | 是 | 否 | 当前实现方向合理 |
| MiniTask 普通编辑 | `group.minitask.updated` | 可选 | 仅被指派人 | 否 | 改标题/截止时间可通知，改描述细节不必刷屏 |
| MiniTask 状态变化 | `group.minitask.updated` | 可选 | 否 | 否 | done/cancelled 通常只刷新看板 |
| MiniTask 截止提醒 | `group.message.created` | 是 | 是 | 否 | 当前实现方向合理 |
| 学生提交/重交 | `submission.created` + `group.message.created` | 是 | 老师待批阅 | 否 | 当前实现方向合理 |
| 老师/助教开始批阅 | `submission.status.updated` | 否 | 可选 | 否 | 不建议写聊天 |
| 批阅反馈创建 | `review.created` + 建议新增 `group.message.created` | 是 | 学生待处理 | 可选 | 当前只推状态，建议补小组反馈提醒 |
| 批阅反馈更新 | `review.updated` | 视是否要求修改 | 可选 | 可选 | 小改不通知，大改或 needs_changes 通知 |
| 成绩草稿创建/编辑 | `grade.draft.updated` 或页面刷新 | 否 | 教师待发布 | 否 | 不通知学生，不进入小组群 |
| 成绩发布 | `grade.published` + 建议新增 `group.message.created` | 是 | 学生成绩角标 | 是 | 当前应强化消息显示 |
| 成绩调整 | `grade.updated` + 建议新增 `group.message.created` | 是 | 学生成绩角标 | 是 | 必须能追溯调整原因 |
| 文件上传 | `material.uploaded` | 否 | 上传者本地 | 否 | 不作为 P0 通知重点 |
| 文件处理失败 | `material.process.failed` | 否 | 上传者/老师 | 可选 | 后续增强 |

## 当前实现与目标差距

### 已经比较合理

- 课程开始/结束写课程系统消息。
- 课程和小组聊天消息支持 created/updated/deleted。
- 小组确认成组和归档写小组系统消息。
- MiniTask 创建、编辑、状态变更有任务事件和小组消息。
- MiniTask 截止提醒和逾期提醒写小组消息并 @ 负责人。
- 学生提交会写小组提交动态，并推送教师侧待批阅事件。
- 成绩发布和调整已经有实时事件和后端权限约束。

### 建议补齐

1. 阶段开放和阶段截止提醒需要更明确的通知策略。
   - 阶段开放：课程公告 + 学生待办。
   - 截止前 24h：未提交小组待办，必要时小组消息。
   - 截止后未提交：教师看板风险 + 学生提交状态提示。

2. 批阅反馈创建建议写入小组系统消息。
   - 尤其是 `needs_changes`，学生必须能明显看到“需要修改”。
   - `approved/rejected` 可只做状态提醒，是否写聊天由产品决定。

3. 成绩发布和成绩调整建议写入小组系统消息。
   - 成绩发布是学生最关心的结果。
   - 成绩调整必须显示调整发生，但具体调整原因可在成绩详情/审计里看，不一定在聊天正文暴露过多。

4. 成绩草稿不通知学生。
   - 草稿属于教师侧中间状态，只需要教师/助教工作台可见。

5. 成员批量导入应聚合通知。
   - 教务/老师看到导入结果即可。
   - 不应给每个学生生成一条课程消息。

6. `assignment.created`、`stage.created` 建议从通知语义上区分草稿创建和正式激活/开放。
   - 草稿创建不通知学生。
   - 激活/开放才通知课程成员。

7. 助教绑定/解绑目前需要补用户级通知。
   - 绑定：通知被绑定助教“你已被授权到课程 X”，通知教务/课程监管“教师 Y 为课程 X 绑定助教 Z”。
   - 解绑：通知被解绑助教“你已从课程 X 移除”，通知教务/课程监管“课程 X 助教 Z 已解绑”。
   - 不建议写课程群，避免学生看到无关管理动作。
   - 不建议建立私聊会话，推荐轻量 `user_notifications` 或 `user:{userId}` 推送。

## 前端显示规则建议

前端不应简单地把所有 realtime event 都弹 toast。

建议显示规则：

- `*.message.created`：更新会话列表未读数；当前会话打开时插入消息。
- `*.message.updated/deleted`：更新当前会话消息，不弹 toast。
- `submission.created`：教师/助教端增加待批阅数量；学生端不弹。
- `submission.status.updated`：当前相关详情页刷新；状态变为 `needs_changes` 时学生端强提醒。
- `review.created`：学生端反馈区出现新反馈；`needs_changes` 强提醒。
- `review.updated`：当前详情页刷新；只有修改为 `needs_changes` 或关键状态变化时提醒。
- `grade.published`：学生端强提醒；老师端状态刷新。
- `grade.updated`：学生端强提醒；老师/教务端审计可查。
- `course.member.updated`：课程成员列表刷新，不弹 toast。
- 教师/助教绑定类管理事件：不进入聊天；受影响用户显示通知中心项或顶部提示，相关课程列表刷新。
- `group.member.updated`：小组成员列表刷新；组长变更可提示。
- `group.minitask.updated`：任务看板刷新；只有被指派、临近截止、逾期时强提醒。

## 验收录屏建议

录屏时建议展示“该出现消息的地方有消息，该只刷新状态的地方不刷屏”。

最小演示链路：

1. 教师激活课程：课程会话出现系统通知。
2. 教师开放阶段：课程侧出现阶段开始提示，学生看到待提交状态。
3. 学生创建 MiniTask 并指派成员：小组群出现任务消息，被指派人有提示。
4. 学生提交阶段成果：小组群出现提交动态，教师待批阅数量增加。
5. 教师提交 `needs_changes` 反馈：学生端出现强提醒，小组可见反馈提示。
6. 学生重交：教师端待批阅恢复。
7. 教师发布成绩：学生端强提醒，成绩可见。
8. 教师调整成绩：学生端再次提醒，教师端说明有审计记录。

不建议录屏展示：

- 登录/登出通知。
- 每个学生导入一条通知。
- 老师查看提交的“已读式”通知。
- 心跳、在线状态等技术事件。

## 落地优先级

### P0：验收前建议完成

1. 明确前端对 `grade.published`、`grade.updated` 的强提醒显示。
2. 明确前端对 `review.created` 且状态为 `needs_changes` 的强提醒显示。
3. 阶段开放和提交截止提醒至少在验收文档中明确口径。
4. 通知验收脚本按“消息显示/状态刷新/审计留痕”分开验证。
5. 助教绑定/解绑按“助教收到授权变化提示、教务/监管侧可见、学生课程群不刷屏”验收。

### P1：录屏后可继续完善

1. 后端为成绩发布、成绩调整补小组系统消息。
2. 后端为 `needs_changes` 批阅反馈补小组系统消息。
3. 阶段截止前提醒进入 worker 或定时任务。
4. 建立事件到前端处理器的矩阵。
5. 增加用户级管理通知表或等价接口，承载教师/助教授权变化。

### P2：后续增强

1. 用户级通知中心。
2. 邮件/企业微信等外部通知。
3. 每日/每周摘要。
4. 文件处理和 AI 任务完成提醒。

# 课程场景与需求

更新时间：2026-06-18

## 一、项目定位

Linksee 是一个面向课程教学协作的软件系统，服务对象包括教务、教师、助教和学生。  
系统围绕一条主链路展开：

`课程建立 -> 项目与阶段发布 -> 学生组队协作 -> 阶段提交 -> 助教/教师批阅 -> 教师确认成绩`

本项目当前目标不是做成完整教务平台，而是优先完成课程项目管理、组队、提交、批阅和评分这一条可验收闭环。

## 二、核心角色

### 1. 教务
- 创建和维护课程
- 绑定课程教师
- 导入和维护课程学生
- 管理用户基础信息与账号状态
- 在条件满足后激活课程

### 2. 教师
- 管理自己课程下的项目和阶段
- 绑定或解绑自己名下助教
- 调整小组、确认成组
- 查看提交、参考助教批阅并最终确认评分

### 3. 助教
- 在被绑定的课程中协助教学管理
- 查看项目、阶段、小组和提交
- 执行批阅，但不负责最终发布成绩

### 4. 学生
- 参与课程
- 创建小组或申请加入已有小组
- 在小组内协作并提交阶段成果
- 查看项目、阶段、说明、附件与本组状态

## 三、当前业务主链路

### 1. 课程准备
- 教务创建课程，课程初始状态为 `draft`
- 教务绑定教师、导入学生
- 教师绑定助教
- 课程满足激活条件后，由教务将课程切换为 `active`

### 2. 项目与阶段组织
- 教师在课程下创建项目
- 每个项目下创建多个阶段
- 阶段可配置说明、提交要求、验收标准和附件
- 项目和阶段按状态推进，不再直接依赖 mock 展示

### 3. 小组形成
- 学生可以创建小组或申请加入小组
- 组长可审批入组、移除成员、发起组长转让
- 教师或助教可以手动调整成员
- 小组正式成立后由 `forming -> active`

### 4. 提交与批阅
- 学生按阶段提交文字、链接和附件
- 提交文件走真实上传链路
- 助教和教师可查看提交详情与附件
- 助教执行批阅，教师在此基础上确认评分

### 5. 成绩确认
- 教师保存评分草稿
- 教师最终发布成绩
- 成绩发布后学生端应能看到稳定回显

## 四、当前状态口径

### 1. 课程状态
- `draft`：已创建但尚未进入正式教学流程
- `active`：课程正式进行中
- `archived`：课程结束或归档

### 2. 项目状态
- `draft`：项目已建立但尚未正式启用
- `active`：项目当前进行中
- `archived`：项目结束或归档

### 3. 阶段状态
- `planned`：已规划但未开放
- `open`：允许提交
- `closed`：已截止
- `archived`：归档保留

### 4. 小组状态
- `forming`：组队中
- `active`：正式成组
- `archived`：归档

## 五、当前关键规则

1. 课程激活前必须至少有一位课程教师和一位已绑定助教。
2. 助教绑定与解绑由课程教师执行，不由教务直接执行。
3. 同一学生在同一项目下只能属于一个小组。
4. 学生组队操作受 `groupFormEnd` 限制；截止后由教师或助教兜底调整。
5. 小组群聊不在学生组队过程中提前建立，应在教学侧确认分组后统一创建。
6. 阶段删除当前按“归档阶段”理解，不是物理删除。
7. 评分草稿保存采用覆盖语义，重复保存不会生成多条草稿。

## 六、当前已实现范围

### 已基本打通
- 教务端课程和用户管理主流程
- 教师端课程、项目、阶段、小组管理主流程
- 学生端组队与提交主流程
- 助教与教师批阅主流程
- 成绩草稿与发布主流程

### 当前仍需收口
- 提交附件展示与下载体验稳定性
- 教师发布成绩后的完整回显
- 小组调整后主界面同步一致性
- 通知规则系统复查
- 真实验收数据准备
- mock 清理与轻量测试补齐

## 七、当前不作为优先交付的能力

以下内容不属于当前最优先验收目标：

- 智能分组策略扩展
- 复杂工单化退组流程
- 完整教务统计分析系统
- AI 助教能力
- 复杂导出报表体系
- 大规模运维监控与自动化告警

## 八、文档使用说明

1. 本文档描述“当前系统实际要交付什么”。
2. 接口字段、请求体与响应体以 OpenAPI 为准。
3. 历史联调口径、旧版前端状态和设计草案不再作为正式需求依据。

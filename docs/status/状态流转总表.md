# 状态流转总表

更新时间：2026-06-18

本文档用于统一课程域核心对象的状态定义、允许流转方向、触发角色与关键副作用。  
如果文档与代码出现不一致，以代码和 OpenAPI 为准，并应尽快同步文档。

## 一、课程

状态值：
- `draft`
- `active`
- `archived`

允许流转：
- `draft -> active`
- `active -> archived`

当前不允许：
- `draft -> archived`
- `active -> draft`
- `archived -> active`

主要触发角色：
- 教务

关键规则：
- 课程激活前必须至少有一位课程教师和一位已绑定助教。
- 激活后课程正式进入教学流程。
- 归档后课程不再参与正常教学流程。

关键副作用：
- 激活课程时创建或激活课程会话
- 向课程成员发送“课程已开始”系统通知
- 归档课程时发送“课程已结束”系统通知

## 二、项目

状态值：
- `draft`
- `active`
- `archived`

允许流转：
- `draft -> active`
- `draft -> archived`
- `active -> archived`

当前不允许：
- `active -> draft`
- `archived -> active`

主要触发角色：
- 教师
- 助教

关键规则：
- 项目激活前至少应存在一个阶段。
- 归档项目后不再参与正常教学流程。

关键副作用：
- 项目激活后，相关阶段进入可继续推进的正式流程
- 项目归档后，相关小组与会话应同步进入归档语义

## 三、阶段

状态值：
- `planned`
- `open`
- `closed`
- `archived`

允许流转：
- `planned -> open`
- `planned -> archived`
- `open -> closed`
- `open -> archived`
- `closed -> archived`

当前不允许：
- `closed -> open`
- `archived -> open`
- `archived -> planned`

主要触发角色：
- 教师
- 助教

关键规则：
- `planned` 表示阶段已建立但未开放
- `open` 表示允许提交
- `closed` 表示阶段已截止
- `archived` 表示归档保留

关键副作用：
- 阶段开放后，学生可进入正式提交流程
- 阶段激活或开放时，应作为后续通知规则候选动作
- 阶段“删除”当前按归档语义理解，不是物理删除

## 四、小组

状态值：
- `forming`
- `active`
- `archived`

允许流转：
- `forming -> active`
- `forming -> archived`
- `active -> archived`

当前不允许：
- `active -> forming`
- `archived -> active`

主要触发角色：
- 学生创建时进入 `forming`
- 教师或助教确认成组后进入 `active`

关键规则：
- 小组正式成立仍按 `forming -> active` 处理
- 如果移除的是组长，系统会自动从剩余成员中补位新组长

关键副作用：
- 小组转为 `active` 时应建立或补齐小组会话
- 组长自动补位后，应发送系统通知

## 五、提交

状态值：
- `not_submitted`
- `submitted`
- `under_review`
- `needs_changes`
- `approved`
- `rejected`
- `reviewed`

允许流转：
- `submitted -> under_review`
- `submitted -> needs_changes`
- `submitted -> approved`
- `submitted -> rejected`
- `under_review -> needs_changes`
- `under_review -> approved`
- `under_review -> rejected`
- `not_submitted -> reviewed`

当前不允许：
- `approved -> submitted`
- `needs_changes -> under_review`（需通过重新提交进入新一轮流程）
- `reviewed -> submitted`

主要触发角色：
- 学生提交后进入 `submitted`
- 助教或教师开始批阅后进入 `under_review`
- 助教或教师提交批阅后进入 `needs_changes / approved / rejected`
- 教学侧可对未提交记录执行人工结案 `not_submitted -> reviewed`

关键规则：
- 只有 `approved` 或 `reviewed` 的提交可以进入评分流程
- 提交文件当前走真实上传与真实下载链路

## 六、批阅

状态值：
- `draft`
- `submitted`

说明：
- 批阅对象本身采用“草稿 / 已提交”语义
- 最终提交后的意见会影响 submission 状态

主要触发角色：
- 助教
- 教师

关键规则：
- 只有教学侧可以创建和更新批阅
- 已有批阅可由作者继续更新

## 七、评分

状态值：
- `draft`
- `published`

允许流转：
- `draft -> published`

当前不允许：
- `published -> draft`

主要触发角色：
- 助教、教师：保存评分草稿
- 教师：发布成绩
- 教师：对已发布成绩执行调整，但状态仍保持 `published`

关键规则：
- 评分草稿保存采用创建或覆盖语义
- 教师是最终成绩确认人

关键副作用：
- 成绩发布后，学生端应能看到最终回显
- 发布动作应触发成绩发布相关事件

## 八、当前最需要继续复查的流转

1. 项目激活后，前端与通知是否同步
2. 阶段开放后，学生可见性与提交入口是否同步
3. 小组 `forming -> active` 后，hero 区、表格、小组会话是否同步
4. 提交 `submitted -> under_review -> approved/needs_changes` 的回显是否稳定
5. 成绩 `draft -> published` 后，教师端与学生端回显是否一致

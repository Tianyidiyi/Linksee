# 视频验收链路对照

更新时间：2026-06-19

## 定位

本文件用于录制验收视频，不等同于完整接口测试。视频只需要证明 Linksee 的核心教学协作链路跑通，并展示各角色主要界面、主要功能和关键状态变化。

录屏原则：

- 只录主链路，不逐个验证所有接口。
- 每一步都要有可见结果，例如列表变化、状态变化、待办数量变化、消息出现、成绩可见。
- 尽量使用已有验收数据，少做现场临时造数。
- 已明确不作为本轮 UI 验收的能力不要硬录，例如已发布成绩调整、完整通知中心、所有文件删除分支。

## 视频结构建议

建议录成一个 15-25 分钟视频，分成 5 段：

1. 项目入口与登录。
2. 教务视角：用户、课程和名单。
3. 教师视角：课程、项目、阶段、助教和批阅。
4. 助教视角：待批阅与反馈。
5. 学生视角：课程、小组、提交、反馈和成绩。

如果时间紧，可以压缩为 10-15 分钟：教务只展示入口和数据存在，重点录教师、助教、学生三端闭环。

## 分角色必须展示的主要界面

### 教务

必须展示：

- 账号登录成功。
- 教师、学生或用户数据入口。
- 课程列表或课程管理入口。
- 已有验收课程存在。

可以一句话说明但不必完整录：

- Excel 导入和批量导入接口已经通过后端集成测试覆盖。
- 视频不逐条验证 200 个学生和 20 个教师。

### 教师

必须展示：

- 教师课程列表。
- 课程详情。
- 项目和阶段。
- 阶段材料或项目附件。
- 助教绑定关系。
- 批阅工作台。
- 成绩发布。

重点对比：

- 学生提交前，待批阅列表没有该新提交或数量较少。
- 学生提交后，教师待批阅列表出现该提交。
- 教师发布成绩前，学生端不显示草稿成绩。
- 教师发布成绩后，学生端显示 published 成绩。

### 助教

必须展示：

- 助教登录后进入助教工作台。
- 能看到被绑定课程。
- 能查看待批阅提交。
- 能打开附件或提交详情。
- 能提交批阅意见。

验收口径：

- 助教负责辅助批阅。
- 成绩发布由教师完成。
- 助教解绑如果前端入口尚未补齐，不在视频中演示。

### 学生

必须展示：

- 学生课程列表。
- 课程项目、阶段和阶段材料。
- 小组成员和 MiniTask。
- 阶段提交。
- 批阅反馈。
- 已发布成绩。

重点对比：

- 提交后状态从未提交/草稿变为已提交。
- `needs_changes` 后学生能看到反馈和修改要求。
- 重交后教师端能继续批阅。
- 成绩发布前不展示草稿分，发布后展示最终成绩。

## 通知与消息录制口径

视频只需要展示“重要状态变化能被用户感知”，不需要证明所有事件都生成通知。

建议展示：

| 场景 | 应展示的结果 |
| --- | --- |
| 学生提交 | 教师/助教待批阅列表变化；小组提交记录可见 |
| 需要修改 | 学生端反馈或状态明显变化 |
| 重交 | 教师/助教端重新出现待批阅 |
| 成绩发布 | 学生端成绩变为可见 |
| MiniTask 指派或更新 | 小组任务区域变化 |

不建议展示：

- 登录/登出通知。
- 心跳、在线状态。
- 每个学生导入一条通知。
- 老师查看提交后的“已读式”提醒。
- 文件上传进度通知。
- 草稿项目/草稿阶段编辑通知。

## 录制时的结果确认方式

每个动作之后建议停留 2-3 秒，口头说明或鼠标指向以下证据：

- 列表新增：新课程、新项目、新阶段、新提交、新任务。
- 状态变化：待提交、已提交、需要修改、已通过、已发布。
- 数字变化：待批阅数量、任务数量、成员数量。
- 权限变化：助教能看到被绑定课程，学生看不到教师端功能。
- 可见性变化：学生只能看到已发布成绩，不看到草稿成绩。

## 视频中不要展开的内容

以下内容可以在文档或口头一句带过，不建议逐项录制：

- 所有 REST 接口逐个调用。
- 所有异常分支和权限错误。
- 200 个学生账号逐个登录。
- 20 门课程逐门检查。
- 所有 Excel 文件逐个导入。
- 已发布成绩调整。
- 用户级通知中心完整实现。
- 聊天消息搜索、编辑、撤回全链路。

## 建议视频结尾总结

结尾建议用 30 秒说明：

1. 教务完成基础数据、课程和名单管理。
2. 教师完成课程、项目、阶段、助教、批阅和成绩发布。
3. 助教完成辅助批阅。
4. 学生完成小组协作、阶段提交、反馈查看和成绩查看。
5. 当前视频证明主业务链路闭环；接口级完整性由集成测试和接口文档补充证明。

# Linksee 完整验收讲稿

本文档用于录制 Linksee 验收视频，内容按“讲解台词 + 前端操作 + 预期结果”的方式组织，适合从头到尾按顺序演示。

## 一、验收前提

- 后端、前端服务已正常启动。
- 正式验收主数据已提前通过脚本导入。
- 现场继续演示导入时，使用 `docs/验收/data/excel` 目录中的增量 Excel 数据。
- 本次验收不依赖 mock，全部基于真实接口和真实数据库。

## 二、使用数据说明

### 1. 正式主数据

由脚本预先写入：

- `scripts/验收/seed-large.mjs`

这部分数据用于保证系统内已经存在一套完整的正式课程、项目、阶段、小组、提交和批阅样例。

### 2. 现场增量导入数据

使用目录：

- `docs/验收/data/excel`

核心文件：

- `增量导入-教师账号.xlsx`

## 五、教务端验收

### 1. 教务登录

账号：

- `2099000001`

讲解台词：

“首先我以教务身份登录。教务端负责课程创建、教师分配、学生导入和课程级基础管理。助教的创建和绑定不由教务负责，而是由对应老师在自己的课程内完成。”

前端操作：

1. 登录教务账号。
2. 进入用户管理页面。

### 2. 导入教师账号

讲解台词：

“我先导入一批新的教师账号，用于现场新增课程演示。这里使用的是一份专门准备的增量教师表。”

前端操作：

1. 点击“导入教师”。
2. 选择 `增量导入-教师账号.xlsx`。
3. 点击确认导入。

预期结果：

- 系统提示导入成功。
- 教师列表中能查到：
  - `2099010101 验收教师甲`
  - `2099010102 验收教师乙`

讲解台词：

“导入完成后，系统返回成功创建的教师数量。现在我可以在教师筛选列表里看到新增的两位老师。”

### 3. 导入学生账号

讲解台词：

“接下来导入现场演示用学生。这样我们后面就可以在真实课程里演示学生分组、提交和批阅回显。”

前端操作：

1. 点击“导入学生”。
2. 选择 `增量导入-学生账号.xlsx`。
3. 点击确认导入。

预期结果：

- 系统提示导入成功。
- 学生列表中能查到：
  - `2099019001 验收学生甲`
  - `2099019010 验收学生癸`

讲解台词：

“系统成功导入了一批新的学生账号。这些账号是专门为了这次现场验收新增的，不会和种子数据冲突。”

### 4. 创建课程

讲解台词：

“接下来我创建一门新的现场演示课程。这门课不会依赖脚本种子里的现成结构，而是通过前端真实操作逐步建立。”

前端操作：

1. 进入课程管理。
2. 点击新建课程。
3. 输入：
   - 课程号：`ACC-LIVE-01`
   - 课程名：`课程协作验收现场演示`
   - 学年、学期按当前口径填写
   - 简介填写简短中文说明
4. 保存。

预期结果：

- 教务端课程列表新增 `ACC-LIVE-01`

讲解台词：

“课程创建成功。此时教务端已经能够看到这门新课，但它还只是课程骨架，后续还需要分配老师并导入学生。”

### 5. 分配老师

讲解台词：

“教务端接下来把课程分配给教师。老师后续会负责创建助教、项目、阶段和小组规则。”

前端操作：

1. 打开 `ACC-LIVE-01`。
2. 添加或分配教师。
3. 选择 `2099010101 验收教师甲`。
4. 保存。

预期结果：

- 课程详情中显示该教师已被分配。

### 6. 导入课程名单

讲解台词：

“接下来导入选课名单。这里使用的是课程名单表，它只包含姓名和一卡通号两列，系统会自动匹配已存在的学生账号。”

前端操作：

1. 在 `ACC-LIVE-01` 课程中点击“导入选课名单”。
2. 选择 `增量名单-ACC-LIVE-01.xlsx`。
3. 点击导入。

预期结果：

- 课程成员中新增 6 名学生。
- 能在成员列表中查到：
  - `2099019001`
  - `2099019002`
  - `2099019004`

讲解台词：

“导入完成后，这门课里就有了一批真实的课程学生。后面我们会切到学生账号验证，确保这些学生确实能在自己的端看到这门课。”

总结台词：

“到这里，教务端完成了新增用户、建课、分配老师和导入学生这几个核心功能。”

## 六、老师端验收

### 1. 老师登录

账号：

- `2099010101`

讲解台词：

“现在切到教师端。老师负责课程内部教学链路，包括创建助教子账号、绑定助教、创建项目、创建阶段，以及后续的小组和批阅管理。”

前端操作：

1. 退出教务。
2. 登录 `2099010101`。
3. 打开 `ACC-LIVE-01`。

预期结果：

- 老师端课程列表中能看到 `ACC-LIVE-01`

### 2. 创建助教子账号

讲解台词：

“根据系统职责设计，助教不是由教务统一创建绑定，而是由老师在自己课程体系内创建和维护。”

前端操作：

1. 打开老师端的助教管理入口。
2. 点击创建助教。
3. 输入：
   - 账号：`2099010201`
   - 姓名：`验收助教甲`
4. 保存。

预期结果：

- 助教列表中出现 `2099010201 验收助教甲`

### 3. 绑定助教到课程

讲解台词：

“助教创建后，还需要真正绑定到课程。只有绑定到课程后，助教端才会看到这门课，并参与批阅流程。”

前端操作：

1. 回到 `ACC-LIVE-01`。
2. 打开助教绑定区域。
3. 选择 `2099010201 验收助教甲`。
4. 点击绑定。

预期结果：

- 课程详情显示助教已绑定
- 助教数量或助教列表同步变化

### 4. 创建项目

讲解台词：

“接下来由老师建立课程内部的项目结构。项目是整个协作流程的核心容器，小组、阶段、提交、批阅都围绕项目展开。”

前端操作：

1. 在左侧层级区点击“新建项目”。
2. 输入：
   - 项目名：`验收演示项目`
   - 状态：`draft`
3. 保存。

预期结果：

- 左侧项目树新增 `验收演示项目`

### 5. 启用项目

讲解台词：

“项目创建后，可以再编辑项目状态。当项目从 draft 切到 active 时，它就正式进入课程协作流程。”

前端操作：

1. 选中 `验收演示项目`。
2. 点击“编辑项目”。
3. 状态切换为 `active`。
4. 保存。

预期结果：

- 项目状态更新为已启用

### 6. 创建阶段

讲解台词：

“项目下面继续建立阶段。阶段用于划分不同教学任务和提交节点。”

前端操作：

1. 在项目下点击“新建阶段”。
2. 新建阶段 1：
   - 标题：`需求与分工`
   - 提交说明：`提交需求说明文档与成员分工表`
   - 验收标准：`需求边界清楚、角色分工明确、风险识别完整`
3. 保存。
4. 再新建阶段 2：
   - 标题：`实现与演示`
   - 提交说明：`提交可运行演示、说明文档与关键截图`
   - 验收标准：`功能可运行、演示闭环完整、说明材料清晰`
5. 保存。

预期结果：

- 左侧项目树中出现两个阶段
- 右侧阶段说明区域同步显示内容

### 7. 启用阶段

讲解台词：

“阶段建好之后，需要切换为正式开放状态，学生才能围绕这个阶段开展协作和提交。”

前端操作：

1. 选择阶段 1 `需求与分工`
2. 点击“编辑阶段”
3. 将状态切换到开放或进行中状态
4. 保存

预期结果：

- 阶段状态变化
- 后续学生端可看到这一阶段结构

总结台词：

“到这里，老师端已经完成了助教创建与绑定、项目创建、阶段创建和项目阶段状态配置。”

## 八、老师端继续验收：一键分组、换组、移除组长

### 1. 一键分组

讲解台词：

“除了手动组队，这套系统还支持老师对未分组学生进行自动分组和成员调整。下面继续验证这几条核心逻辑。”

预期结果：

### 2. 换组

讲解台词：

“接着验证成员换组功能。这个操作会真正改变学生所属小组，不是只改前端展示。”

2. 选择目标组
3. 确认

预期结果：

- 原组人数减少

- 学生重新登录后能看到所属组变化

### 3. 移除组长并自动转移组长

讲解台词：

“现在验证一个更关键的业务规则。如果移除的是组长，系统需要自动把当前组里最早加入的剩余成员提升为新组长。”

前端操作：

1. 在某个小组中对当前组长点击“移除”
2. 确认操作

预期结果：

- 原组长被移出当前组

- 成员角色显示同步变化

补充台词：

“这说明组长转移不是手工补救，而是系统内置规则自动完成。”

# 前后端衔接问题检查清单

更新时间：2026-06-19

## 检查口径

本清单只记录“后端已有或已设计，但前端入口、交互、状态展示、通知显示可能没有完全接上”的问题。它不替代接口文档，也不要求在本线程直接改前端 UI。

优先级说明：

- P0：影响录屏验收主链路，需要验收前明确处理或调整验收口径。
- P1：不阻断主链路，但会影响完整性或体验。
- P2：后续增强。

## 一、助教绑定、解绑与通知

### 1.1 课程助教解绑入口缺失

优先级：P0

后端状态：

- 已有 `GET /api/v1/courses/:id/assistants`。
- 已有 `POST /api/v1/courses/:id/assistants`。
- 已有 `DELETE /api/v1/courses/:id/assistants/:assistantUserId`。
- 解绑限制：只有课程老师能解绑自己绑定的助教，归档课程不可变更。

前端状态：

- 教师扩展工作台已调用助教列表接口。
- 教师扩展工作台已调用课程助教绑定接口。
- 未看到教师端对 `DELETE /api/v1/courses/:id/assistants/:assistantUserId` 的实际调用。

影响：

- 录屏可以演示“绑定助教”，但不能完整演示“解绑助教”。
- 用户提出的“只有一个助教账号的老师继续开通助教验证”可做，但“开通后解绑/变更授权”链路不完整。

建议：

- 教师端助教列表每行增加“解绑”操作。
- 解绑后刷新课程助教列表和助教端课程列表。
- 验收时确认被解绑助教不能再查看该课程的待批阅和课程内容。

### 1.2 助教绑定/解绑通知尚未形成完整闭环

优先级：P0

目标策略：

- 老师绑定助教：通知被绑定助教“你已被授权到课程 X”；通知教务/课程监管“教师 Y 为课程 X 绑定助教 Z”。
- 老师解绑助教：通知被解绑助教“你已从课程 X 移除”；通知教务/课程监管“课程 X 助教 Z 已解绑”。
- 不进入课程群，不打扰学生。

当前状态：

- 后端有绑定/解绑接口，但没有看到专门的用户级通知事件或通知表。
- 当前 Socket 房间以 `course:*`、`group:*` 为主，管理通知更适合走 `user:*` 或通知中心。

建议：

- 短期验收口径：绑定/解绑后通过助教端课程列表变化证明授权生效。
- 后续实现：增加用户级管理通知，例如 `course.assistant.bound`、`course.assistant.unbound`，并保留审计记录。

### 1.3 助教账号创建、编辑与课程绑定是两条链

优先级：P1

后端状态：

- `POST /api/v1/users/assistants` 创建老师名下助教账号。
- `GET /api/v1/users/assistants/mine` 查询老师名下助教。
- `PATCH /api/v1/users/assistants/:assistantUserId` 编辑或停用助教账号。
- `POST /api/v1/courses/:id/assistants` 才是课程授权。

前端状态：

- `user-settings.js` 可创建/编辑助教账号。
- `dashboard-extensions.js` 可将已有助教绑定到课程。

风险：

- 如果录屏只创建助教账号，但没有绑定课程，助教登录后不会看到课程内容。

建议：

- 验收脚本明确拆成两步：先创建助教账号，再绑定到课程。
- 助教登录验收前，先确认该助教有至少一条 `assistant_bindings`。

## 二、项目与阶段附件上传、删除

### 2.1 项目附件删除未接到前端

优先级：P0

后端状态：

- 已有 `POST /api/v1/assignments/:assignmentId/materials` 上传项目附件。
- 已有 `DELETE /api/v1/assignments/:assignmentId/materials` 删除项目附件。
- 删除需要 `objectKey`，可放在 body 或 query。
- 删除会从 `descriptionFiles` 移除元数据，并清理 MinIO 对象。

前端状态：

- 教师扩展工作台已调用项目附件上传接口。
- 教师附件区能展示项目附件数量和文件信息。
- 未看到对 `DELETE /api/v1/assignments/:assignmentId/materials` 的调用。
- 附件列表当前主要展示文件名、大小、时间，未看到删除按钮。

影响：

- 老师上传错项目附件后，前端无法清理。
- 验收“项目文件清理删除”会卡住。

建议：

- 教师端附件列表中，为项目附件增加“删除”按钮。
- 删除时调用 `DELETE /api/v1/assignments/:assignmentId/materials`，传 `objectKey`。
- 删除后刷新项目详情和附件列表。

### 2.2 阶段附件删除未接到前端

优先级：P0

后端状态：

- 已有 `POST /api/v1/stages/:stageId/materials` 上传阶段附件。
- 已有 `DELETE /api/v1/stages/:stageId/materials` 删除阶段附件。
- 删除需要 `objectKey`。
- 删除会从 `requirementFiles` 移除元数据，并清理 MinIO 对象。

前端状态：

- 教师扩展工作台已调用阶段附件上传接口。
- 学生端可展示并下载阶段材料。
- 未看到对 `DELETE /api/v1/stages/:stageId/materials` 的调用。

影响：

- 老师上传错阶段材料后无法在前端删除。
- 学生端可能继续看到不应展示的过期材料，除非后端数据手工清理。

建议：

- 教师端附件列表区分“项目附件”和“阶段附件”。
- 阶段附件删除时调用 `DELETE /api/v1/stages/:stageId/materials`，传 `objectKey`。
- 删除后刷新阶段详情，学生端同步不再显示该材料。

### 2.3 阶段删除是“归档”，不是物理删除

优先级：P1

后端状态：

- `DELETE /api/v1/stages/:stageId` 当前语义是把阶段状态置为 `archived`。
- 不物理删除阶段，也不自动清理阶段附件对象。

前端状态：

- 教师端按钮文案已经偏“归档成功”，与后端语义基本一致。

风险：

- 如果验收人员把“删除阶段”理解为物理删除和文件清理，会产生误解。

建议：

- 录屏时统一说“归档阶段”。
- 如果确实需要物理删除阶段，需要单独设计删除条件、附件清理、提交记录处理和审计规则。

### 2.4 项目删除只允许 draft 且无下游数据

优先级：P1

后端状态：

- `DELETE /api/v1/assignments/:assignmentId` 只允许删除 draft 项目。
- 若已有阶段、小组或分组配置，会返回冲突。
- 删除 draft 项目时会清理项目附件对象。

前端状态：

- 教师扩展工作台有项目删除调用。

建议：

- 删除按钮旁提示：只有草稿且无阶段/小组的项目可以删除。
- 已激活或已有数据的项目应走归档，不走物理删除。

## 三、批阅、成绩与助教端差异

### 3.1 助教端成绩权限

优先级：已对齐

后端状态：

- 助教可创建和修改成绩草稿。
- 只有老师可发布成绩和调整已发布成绩。

前端状态：

- 教师端可创建成绩草稿和发布成绩。
- 助教端可保存成绩草稿，但不显示发布入口。

建议：

- 当前验收口径保持：助教可批阅和保存草稿分，教师负责最终发布。

### 3.2 批阅记录编辑入口不清晰

优先级：后端保留，本轮不验收

后端状态：

- 已有 `PATCH /api/v1/reviews/:reviewId`。

前端状态：

- 批阅工作台展示历史尝试和批阅动作，但本轮不提供“修改批阅”入口。

建议：

- 维持后端接口，不删除；前端隐藏入口，不作为当前 UI 验收项。

### 3.3 已发布成绩调整入口

优先级：后端保留，本轮不验收

后端状态：

- 已有 `PATCH /api/v1/grades/:gradeId`。

前端状态：

- 教师端发布成绩链路可跑；已发布成绩调整入口、调整原因输入和调整日志展示本轮不做。

建议：

- 不删除后端接口；前端不展示入口。
- 学生端必须只看到 published 结果，不看到草稿分。

## 四、实时事件与前端处理器差异

### 4.1 前端事件类型落后于后端事件目录

优先级：P1

后端事件目录包含：

- `course.conversation.activated`
- `course.member.updated`
- `group.member.updated`
- `review.updated`
- `grade.updated`
- `material.*`

前端 `src/realtime/event-handlers.ts` 当前类型未完整覆盖上述事件。

影响：

- 如果正式前端后续使用 TypeScript realtime 客户端统一处理事件，会漏掉部分状态刷新。
- 批阅更新、成员变化等可能只靠手动刷新才能看到；成绩调整本轮前端不覆盖。

建议：

- 补齐前端事件类型。
- 建立“事件 -> 前端处理器 -> 页面可见效果”矩阵。

### 4.2 助教绑定/解绑需要用户级通知，不适合课程群

优先级：P1

当前 Socket 房间以课程和小组为主。助教授权变化是个人权限变化，不应广播给学生。

建议：

- 增加用户级通知能力，或短期在助教端登录/刷新时提示课程授权变化。
- 教务端显示授权变更摘要，作为监管记录。

## 五、建议验收前确认顺序

1. 先确认助教绑定后，助教能看到课程和待批阅。
2. 再确认助教解绑入口是否存在；若不存在，录屏不演示解绑，只把它列为待补。
3. 确认项目附件和阶段附件是否能上传、展示、下载。
4. 确认项目附件和阶段附件是否能删除；若不能，录屏不演示“清理删除”，列为待补。
5. 确认阶段是归档不是物理删除，录屏统一用“归档阶段”措辞。
6. 确认教师端成绩发布后，学生端能看到成绩。
7. 已发布成绩调整、人工结案、批阅记录二次编辑不进入本轮 UI 验收。
8. 确认 `needs_changes`、`grade.published` 前端是否有强提醒；没有则以状态刷新作为短期验收口径。
## 2026-06-19 批阅与评分当前结论

当前前端验收不再把“已发布成绩调整入口”“人工结案入口”“批阅记录二次编辑入口”列为必须补齐项。

- `PATCH /api/v1/grades/:gradeId`：后端保留，用于后续已发布成绩调整；本轮 UI 不做入口。
- `POST /api/v1/submissions/:submissionId/mark-reviewed`：后端保留，用于后续人工结案；本轮 UI 不做入口。
- `PATCH /api/v1/reviews/:reviewId`：后端保留，用于后续批阅记录编辑；本轮 UI 不做入口。

当前 UI 验收主链路为：提交 -> 一人批阅最终态 -> 保存评分草稿 -> 教师发布成绩 -> 学生查看已发布成绩。

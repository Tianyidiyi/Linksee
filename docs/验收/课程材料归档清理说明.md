# 课程材料归档清理说明

更新时间：2026-06-19

## 当前口径

项目附件和阶段附件不在教师端 UI 里做普通手动删除入口。正式清理走后端生命周期任务：

- 项目状态为 `archived` 后，项目附件进入清理候选。
- 阶段状态为 `archived`，或所属项目已经 `archived` 后，阶段附件进入清理候选。
- 默认保留期为 180 天；可通过 `COURSE_MATERIAL_RETENTION_DAYS` 配置。设为 `0` 时，归档后下一次任务执行即可清理。

## 执行方式

```bash
npm run cleanup:course-materials -w @linksee/api
```

建议后续由 cron、CI 定时任务或部署平台调度执行。

Worker 定时调度入口：

```bash
npm run start:course-material-cleanup-scheduler -w @linksee/worker
```

默认调度间隔为 1440 分钟，也就是每天扫描一次；可通过 `COURSE_MATERIAL_CLEANUP_INTERVAL_MINUTES` 调整。扫描频率不等于保留期，是否真正删除仍由 `COURSE_MATERIAL_RETENTION_DAYS` 判断。

## 清理行为

任务会先在数据库事务中清空对应 JSON 附件引用：

- `assignments.description_files`
- `assignment_stages.requirement_files`

事务成功后，再按 `objectKey` 删除 MinIO 中的课程材料对象。对象删除使用幂等策略，缺失对象不会阻断任务。

如果配置了 `COURSE_MATERIAL_CLEANUP_SENDER_ID`，任务会向课程会话写入一条系统通知；未配置时只执行清理，不强行使用不存在的系统用户。

## 验收关注

- 归档未超过保留期：附件仍保留。
- 归档超过保留期：接口返回的项目/阶段附件列表为空，学生端不再展示该材料。
- 配置通知发送人后：课程会话出现材料清理系统通知。

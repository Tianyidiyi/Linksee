# Linksee 后端验收流程

## 数据准备

两种方式二选一：

1. 页面导入：使用 `docs/验收/data/excel/` 下的 Excel 文件导入教师、学生和课程名单。
2. 正式验收直接写库：运行 `scripts/验收/seed-large.mjs`，一次性写入用户、身份、课程、项目、阶段、小组、minitask、会话、提交、批阅和成绩。
3. 快速冒烟直接写库：运行 `scripts/验收/seed-smoke.mjs`。

默认验收密码：`Accept123!`

## 账号

- 教务：`2099000001`
- 教师：`2099000101` 到 `2099000120`
- 助教：`2099000201` 起，共 30 个；每个教师 1-2 个助教
- 学生：`2099001001` 到 `2099001200`
- 课程：`ACC-2026-01` 到 `ACC-2026-20`

教师 `2099000101` 只有 1 个助教，适合后续验证“继续开通助教账号”。

## 验收路径

1. 教务验收
   - 登录教务账号。
   - 导入教师、学生。
   - 检查 20 门已有验收课程。
   - 每门课程绑定教师，并按教师配置 1-2 个助教。
   - 导入课程名单，确认学生成员能匹配姓名和一卡通号。
   - 现场新建 1 门课程，建议课程号 `ACC-2026-NEW`，用于验证新增课程流程。

2. 教师验收
   - 登录教师 A。
   - 进入 `ACC-2026-01`，确认该课程有 2 个项目；大多数课程只有 1 个项目。
   - 检查项目阶段、分组、组员、minitask。
   - 在现场新建课程或已有课程下新建 1 个项目。
   - 在新建项目下新建 1 个阶段。
   - 打开待批阅提交，执行提交批阅、保存成绩草稿、发布成绩。
   - 已发布成绩调整本轮不做前端入口，不作为当前 UI 验收项。

3. 助教验收
   - 登录助教账号。
   - 进入被绑定课程。
   - 确认可以查看并处理待批阅提交。
   - 当前验收口径下，助教可保存成绩草稿，但不提供成绩发布入口。

4. 学生验收
   - 登录学生账号。
   - 查看加入课程、项目、小组。
   - 查看并维护 minitask。
   - 在课程会话和小组会话中确认消息存在。
   - 查看已发布成绩；未发布成绩应显示未发布或不可见，不应展示 draft 分数。

5. 成绩审核发布重点验收
   - pending review：提交物进入待批阅列表。
   - review：教师或助教能提交批阅意见。
   - grade draft：教师和助教能根据已通过批阅保存成绩草稿。
   - publish：教师能发布成绩。
   - adjustment：后端保留能力，本轮前端不验收。
   - student visibility：学生只看到 published 成绩。

6. 通知链路重点验收
   - 课程开始/结束、项目激活、阶段开放：属于课程层通知。
   - 小组成立、组长变更、MiniTask 指派、提交动态：属于小组层通知。
   - 助教绑定/解绑、教师指派/移除：属于用户级管理通知；助教和教务/监管侧应可见，不进入学生课程群。
   - 批阅 `needs_changes`、成绩发布：属于学生强提醒；成绩调整本轮不做前端入口。
   - 开始批阅、成员列表刷新、看板聚合变化：只要求状态刷新，不要求聊天消息。
   - 批量导入、登录登出、心跳、已读状态：不作为业务通知验收。
## 2026-06-19 批阅与评分当前口径

当前验收主链路采用“一人批阅即最终态”：教师或助教提交批阅后，提交进入 `approved / needs_changes / rejected` 之一，不做多人评审聚合。

助教可以参与批阅并保存评分草稿，但不提供成绩发布入口；成绩发布仅由教师完成。

已发布成绩调整、人工结案和已提交批阅二次编辑均属于后端保留能力，本轮前端不提供入口，不作为当前 UI 验收项。相关接口不删除，避免影响后端契约、OpenAPI 和集成测试。
